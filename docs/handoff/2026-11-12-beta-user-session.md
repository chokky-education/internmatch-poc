# Handoff: เซสชัน "เพิ่ม User Beta" (2026-11-12)

สรุปสำหรับ agent ที่มารับช่วงต่อ: เรื่องที่คุยกัน, ข้อสรุป และสิ่งที่ยังค้างอยู่ (ไม่ใส่อีเมลจริง เพราะ repo นี้เป็นสาธารณะ)

## 1. เพิ่มผู้ใช้ beta
- รายชื่ออีเมลที่เข้าใช้ได้อยู่ใน Worker secret `ALLOWED_EMAILS` (คั่นด้วย `,`, อ่านที่ `worker/src/auth.js:11`) ไม่ต้องแก้โค้ด
- `wrangler secret put` **เขียนทับค่าเดิมทั้งหมด** และอ่านค่าเดิมกลับมาไม่ได้ จึงต้องใส่อีเมลเดิมทั้งหมดต่อด้วยอีเมลใหม่ ผู้ใช้รันคำสั่งเอง
- ตามที่ได้ยินมา ผู้ใช้ตั้งค่าแล้ว แต่ไม่มีใครเช็กผลการล็อกอินจริง

## 2. ยกเลิกการผูก LINE
- **ระบบยังไม่มีวิธียกเลิกการผูก LINE** ปุ่ม "ออกจากระบบ" บนเว็บลบแค่ session ของเว็บ
- ผู้ใช้รันเองบน D1 `internmatch`: `UPDATE users SET line_user_id=NULL WHERE email=...` คำสั่งรันผ่านโดยไม่มี error แต่ไม่มีใครยืนยันผล
- อาจทำต่อเป็นฟีเจอร์ได้: คำสั่ง "ยกเลิกการผูก" ใน LINE + ปุ่มบนเว็บ ที่เรียกฟังก์ชันเดียวกันใน `worker/` (ยังไม่ได้ทำ)

## 3. ⚠️ โควตา D1 หมด (ยังไม่แก้)
- error 7500: บัญชีใช้โควตาอ่านแถว D1 แบบฟรีของวันหมด ตอนนั้นแอปใช้งานแทบไม่ได้ โควตารีเซ็ตทุกวัน 00:00 UTC (07:00 เวลาไทย)
- ผู้ใช้ไม่กี่คนไม่ควรใช้ถึง 5M แถว/วัน ต้นเหตุที่น่าสงสัยคือ cron เตือนทุก 15 นาที (`sendDueReminders`) ที่อาจสแกนทั้งตาราง/ไม่มี index **ยังไม่ได้ตรวจ**
- ลบโปรเจกต์อื่นไม่ช่วยโควตาที่ใช้ไปแล้ว ช่วยได้เฉพาะเมื่อโปรเจกต์นั้นเป็นตัวกินโควตา ให้ดู D1 → Metrics → Rows read ก่อน

## 4. ระบบแจ้งเตือนเวลาล่ม (ยังไม่มี)
- ผู้ใช้เว็บเห็น "ตรวจอินเทอร์เน็ต" (ผิด), LINE ตอบ "พี่ขัดข้อง", cron ล้มแบบเงียบ, admin ไม่ได้รับแจ้งเลย (มีแค่ `console.error`)
- ที่เสนอไว้ เรียงตามลำดับ: (1) แก้ต้นเหตุโควตา (2) แยก error D1 → ตอบ 503 พร้อมข้อความ "กลับมาใช้ได้หลัง 07:00" ทั้งบนเว็บและ LINE (3) แจ้ง admin ผ่าน LINE/อีเมล ไม่เกินครั้งละชั่วโมง (4) ตั้ง Cloudflare Notifications

## 5. กลยุทธ์ขอบเขตโปรดักต์
- จากภาพที่ผู้ใช้วาด แบ่ง 2 แกน: ช่วงเวลา (ก่อนฝึก ⭕ ทำอยู่ / กำลังฝึก / ฝึกเสร็จ) × ประเภทการฝึก (ฝึกหลายรอบปี 1–3 / ฝึกครั้งเดียวปี 4)
- ข้อสรุป: **วิสัยทัศน์ครบทั้งเส้นทาง แต่เวอร์ชันนี้โฟกัสก่อนฝึกงาน** และขยายเมื่อมีหลักฐานจากผู้ใช้ ความเสี่ยงหลักคือผู้ใช้หายทันทีที่ได้ที่ฝึก
- โพสต์ข้อเสนอนี้ใน Slack #product-strategy แล้ว (รอความเห็นทีม)
